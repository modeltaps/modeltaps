# 画像ストレージ

Cloudflare Workers AI と Stability AI の画像 API、および Gemini の画像出力は、リンクではなく画像データを返します。既定では、Modeltaps はこれらの画像をゲートウェイ自身に一時保管し、サイト自身のアドレスで一時リンクを返します。第三者のストレージは不要です。外部ストレージに切り替えることもできます。無効にすると、これらの応答は base64 になります。画像 API は `url` ではなく `b64_json` を返し、Gemini の応答には `data:image/png;base64,...` がそのまま埋め込まれるため、画像 URL だけを読むクライアントには画像が届きません。

DALL·E や Flux などのアップストリームは画像リンクを直接返します。**アップストリームが返す画像リンクも保管する**（既定で有効）は、チャネルのプロキシ経由で一度取得して画像ストレージに保管し、クライアントにはこのサイトのリンクを返します。アップストリームのホストがブロックされている、または遅い環境でも使えます。取得に失敗した場合はアップストリームのリンクをそのまま返します。無効にするとリンクはそのまま渡されます。

## 既定：このゲートウェイ

画像はゲートウェイに保管され、リンクは `<サーバーアドレス>/media/<ランダムな名前>.png` の形になります。

- リンクは 1 時間で失効し、ファイルは削除されます（10 分ごとに掃除します）。
- 1 つのリンクは 5 回までダウンロードでき、6 回目以降は `410` を返します。公開の画像ホスティングとして転用できません。
- 1 回のダウンロードは 2 MB/s までで、1 ノードが同時に返すのは 16 件までです。超えると `429` を返します。

リンクには **プラットフォーム管理 → サイト → サーバーアドレス** を使うので、呼び出し元から届くアドレスを設定してください。Redis がない場合、ファイルはデータディレクトリの `data/media`（`media_dir` で変更可）に書き込まれ、単一ノード向けです。Redis を有効にすると画像は Redis に保管されて期限切れで消え、どのノードでもリンクを返せます。複数ノード構成では Redis が必要です。

## 管理画面で設定する

**プラットフォーム管理 → ゲートウェイ設定 → リクエストとプロトコル → 画像ストレージ** でストレージを選び、項目を入力します。保存するとすぐに反映され、再起動は不要です。複数ノード構成では設定の同期で各ノードに反映されます。シークレットは暗号化して保存され、画面にはマスクだけが表示されます。空欄のまま保存すると変更されません。

**テストアップロード** はフォームの現在の内容で小さな画像をアップロードし、リンクとサムネイルを表示します。保存は不要です。シークレットが空欄の場合、保存済みのシークレットは保存済みのエンドポイント・バケット・アクセスキー ID に対してだけ使われます。

同時に使うストレージは 1 つです。外部ストレージはストレージ自身のリンクを返すため、上記のダウンロード回数や速度の制限はかからず、ゲートウェイが削除することもありません。

| ストレージ | 必須 | 補足 |
|---|---|---|
| このゲートウェイ（既定） | なし | 上記を参照 |
| S3 互換ストレージ | エンドポイント、バケット、アクセスキー ID、アクセスキーシークレット | AWS S3、Cloudflare R2、MinIO、Backblaze B2 など |
| Alibaba Cloud OSS | エンドポイント、バケット、アクセスキー ID、アクセスキーシークレット | 1 時間有効な署名付きリンクを返すため、バケットは非公開のままで構いません |
| SM.MS | API トークン | 無料の画像ホスティング。画像は公開されます |
| Imgur | クライアント ID | 無料の画像ホスティング。画像は公開されます |

S3 の署名にはリージョンが必要です。Cloudflare R2 は `auto` を使うので空欄で構いません。AWS S3、Backblaze B2、Wasabi の標準エンドポイント（`https://s3.us-west-2.amazonaws.com`、`https://s3.us-west-004.backblazeb2.com` など）からは自動で判定します。その他のサービスはそのドキュメントに従って入力してください。呼び出し元には公開 URL の下の通常リンク（空欄なら `endpoint/bucket`）が返るため、バケットは公開読み取りを許可する必要があります。Expires ヘッダーの日数はオブジェクトの Expires ヘッダーに書き込むだけで、ファイルは削除しません。自動削除はストレージ側のライフサイクルルールで設定してください。

Alibaba Cloud OSS のアップロードと署名付きリンクは V4 署名を使います（2025 年以降、新しいアカウントとバケットは V1 署名を受け付けません）。V4 署名にはバケットのリージョンが必要です。`oss-cn-beijing.aliyuncs.com` のような標準エンドポイントなら空欄で構いませんが、カスタムドメインや転送アクセラレーションのエンドポイントでは入力が必要です。

### 例：Cloudflare R2

R2 はダウンロードの転送料金がかからないため、画像ホスティングに向いています。

1. Cloudflare ダッシュボードの R2 でバケットを作成し、概要ページのアカウント ID を控えます。
2. バケット設定の **Public access** でカスタムドメインを接続します。`r2.dev` サブドメインも使えますが、レート制限があり、テスト向けです。
3. **Manage R2 API Tokens** でトークンを作成し、権限は **Object Read & Write**、対象はこのバケットだけにします。表示される Access Key ID と Secret Access Key は一度しか表示されないので控えておきます。

画像ストレージには次のように入力します。

| 項目 | 入力内容 |
|---|---|
| ストレージ | S3 互換ストレージ |
| エンドポイント | `https://<アカウント ID>.r2.cloudflarestorage.com`（EU 管轄のバケットは `https://<アカウント ID>.eu.r2.cloudflarestorage.com`） |
| リージョン | 空欄。`auto` が使われます |
| バケット | バケット名 |
| アクセスキー ID | トークンの Access Key ID |
| アクセスキーシークレット | トークンの Secret Access Key |
| 公開 URL | カスタムドメイン（`https://img.example.com` など）または `https://pub-xxxx.r2.dev`。R2 のエンドポイントは公開アクセスできないため必須です |
| Expires ヘッダー（日） | `0` |

**テストアップロード** を押してサムネイルが表示されれば設定は正しいので、保存します。古い画像を定期的に削除するには、バケット設定の **Object lifecycle rules** に削除ルール（例：30 日後に削除）を追加します。

## 設定ファイルからのアップグレード

旧バージョンでは `config.yaml` の `storage:` セクション（または対応する `STORAGE_*` 環境変数）で画像ストレージを設定していました。アップグレード後の最初の起動時に、この設定は自動で管理画面に移されます。以降 `storage:` セクションは読まれないので削除できます。旧バージョンは複数のストレージを設定でき、決まっていない順序で試していました。移行時は 1 つだけ残し、S3、Alibaba Cloud OSS、SM.MS、Imgur の順に優先します。
