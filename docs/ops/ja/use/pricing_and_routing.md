# 価格、コスト、供給の順番

このページでは、Modeltaps がユーザーの支払額、リクエストのコスト、リクエストを受ける供給をどう決めるかを説明します。各設定の場所と計算例も載せています。

## 3 つの数値

| 数値 | 内容 | 見える人 |
|---|---|---|
| **カタログ価格** | モデルの公式 API 価格（100 万トークンあたり、またはリクエスト・分あたり） | 全員（価格ページ） |
| **グループ倍率** | ユーザーグループごとにカタログ価格に掛ける倍率。`default` グループの倍率がサイトの通常価格です | ユーザーは自分のグループの価格を見ます |
| **チャネルコスト** | 上流があなたに請求する額：チャネルの表示価格 ×（1 + 手数料率） | 管理者のみ |

ユーザーが支払うのは常に **カタログ価格 × グループ倍率** です。リクエストを処理したチャネルによって変わりません。チャネルコストはユーザーに転嫁されず、どの供給がリクエストを受けるか、価格チェックがどの供給を止めるかだけを決めます。

リクエストあたりの粗利：

> カタログ価格 × グループ倍率 ×（1 − 決済コスト率）− チャネルコスト

**決済コスト率** は、あなたが代金を受け取るときにかかる割合（カード手数料、為替コスト）です。誰にも請求されず、コストと比べる純収入を下げるためだけに使います。

## 設定する場所

| 設定内容 | コンソールの場所 | 設定 / 項目 |
|---|---|---|
| カタログ価格 | **モデル** → モデル → 価格、または価格ソースから同期 | モデル価格 |
| サイトの利益 | **ユーザー → ユーザーグループ** → `default` グループ → 倍率（1.12 = 公式価格より 12% 高い） | `user_groups.ratio` |
| 割引・割増グループ | **ユーザー → ユーザーグループ** → その他のグループ | `user_groups.ratio` |
| 決済コスト率 | **プラットフォーム設定 → 課金 → 料金設定** → 決済コスト率 | `PaymentCostPercent` |
| 試算 | 同じカード：試す既定グループ倍率を入力（保存されません） | — |
| チャネルの表示価格 | **チャネル** → チャネル → 価格（上流から同期）。価格表のない中継：詳細 → コスト倍率 | `channel_prices`、`cost_ratio` |
| チャネル手数料率 | **チャネル** → チャネル → 詳細 → 手数料率、またはチャージ記録 | `fee_rate`、`fee_note` |
| 同じ層での分担 | **プラットフォーム設定 → ゲートウェイ → 割り当て → 供給モードとコスト** → 同じ層の中。モデルごとには「供給」タブで変更 | `SupplyModeDefault`、モデルの供給モード |
| コストと優先度 | 同じカード → コストと優先度 | `SupplyCostOrder` |
| 層の順番 | **プラットフォーム設定 → ゲートウェイ → 割り当て** → 割り当てポリシー。手動モデルは「供給」タブ | 割り当てポリシー、供給の優先度 |

## チャネル手数料率

手数料率は、プロバイダーが表示価格とは別に請求する割合です。多くのプロバイダーはクレジット購入時に請求するので：

> 手数料率 = 支払った現金 ÷ 受け取ったクレジット − 1

新しいチャネルは、プロバイダーが公表している手数料率から始まります。公表されていない場合は、決済画面で確認した手数料率を使います：

| プロバイダー | 既定 | 出典 |
|---|---|---|
| Requesty | 5% | 課金ドキュメントのチャージ手数料 |
| OpenRouter | 5.5% | FAQ のクレジット購入手数料（最低 $0.80、暗号資産 5%） |
| Vercel AI Gateway | 3% | Vercel のドキュメントには記載がなく、決済手数料は購入者負担とだけあります。2026-11-18 の決済画面では $100 のクレジットに $3.00 の手数料 |
| 公式ベンダー API、その他の中継 | 0% | — |

**チャネル → 詳細 → チャージ記録** に実際のチャージを記録します。支払った現金（カード・為替手数料込み）と受け取ったクレジットです。以後、手数料率は直近 10 件のチャージから算出され、既定値を置き換えます。ボーナスクレジットで手数料率が負になることはありません。

## どの供給がリクエストを受けるか

1. まず優先度で並べます（割り当てポリシー、または手動モデル自身の数値）。
2. 次にコストで分けます。最も安い供給だけがリクエストを受け、割高な供給はより安い供給がすべて使えないときだけ使われます。コスト不明の供給は最後です。差が 0.1% 以内なら同じ価格とみなします。
3. リクエストを受ける供給の間では供給モードに従います。**負荷分散** は重みで分担し、**フェイルオーバー** は最も重い供給にすべて送ります。

**コストと優先度**（`SupplyCostOrder`）は、手順 2 がどこまで及ぶかを決めます：

- **優先度を優先**（既定）：コストは同じ優先度の中の順番だけを変えます。優先度がコスト以外（品質、速度、信頼するプロバイダー）を表すときに選びます。
- **コストを優先**：優先度に関係なく、モデルの最も安い供給がリクエストを受けます。優先度は同じコストの供給の順番だけを決めます。安いホストは遅い、または量子化モデルの場合があるので、切り替える前に供給を確認してください。

モデルの「供給」タブには、リクエストが実際に試す順番が表示されます。割高なだけで後ろに回った予備には **割高・予備のみ** と表示されます。

## 価格チェック

サイトの通常価格による純収入よりコストが高い供給は、リクエストを受けるたびに損失が出ます。判定ラインは：

> default グループ倍率 ×（1 − 決済コスト率）

利益を設定すると（判定ラインが 1 を超えると）、ラインを超える新しい供給は確認待ちになり、既存の予備も確認待ちとして無効になります。リクエストを受けている供給は止めず、管理者に通知します。**料金設定** カードには、各チャネルの損益分岐倍率、損失が出る供給、各ユーザーグループの純収入が表示されます。

割引グループは判定に使いません。割引はあなた自身の選択だからです。それでも料金設定カードには、各グループでどのチャネルが損失になるかが表示されます。

## 計算例

### 1. 公式価格より 12% 高く売る

`default` グループの倍率を **1.12**、決済コスト率を **4%** にします。カタログ価格 $1 あたりの純収入は 1.12 × 0.96 = **$1.0752** です。

| チャネル | カタログ価格 $1 あたりのコスト | 粗利 |
|---|---|---|
| 公式 API | $1.00 | 7.5% |
| Vercel AI Gateway（3%） | $1.03 | 4.4% |
| Requesty（5%） | $1.05 | 2.4% |
| OpenRouter（5.5%） | $1.055 | 1.9% |

default グループのユーザーが 100 万トークンあたり $3 / $15 のモデルを呼ぶと、どのチャネルが処理しても $3.36 / $16.80 を支払います。

### 2. Vercel のチャージを記録する

**$103.00** を支払い、**$100.00** の AI クレジットを受け取りました。支払い 103、受け取り 100 でチャージ記録を追加すると、手数料率は 3% になり、メモにはチャージ記録から算出したことが書かれます。次のチャージが $206.40 で $200 なら、手数料率は (103 + 206.40) ÷ 300 − 1 = 3.13% になります。

### 3. 同じ優先度の 2 つの供給

`glm-5.2` を Vercel（コスト ×1.03）と Requesty（コスト ×1.05）が同じ優先度・負荷分散で供給しています。リクエストはすべて Vercel に送られ、Vercel が一時停止中かエラーのときだけ Requesty が受けます。default グループのユーザーの支払額はどちらでも同じです。

### 4. 優先度を超えてコストを優先する

`gpt-5.1` を最上位の優先度で Requesty（コスト ×1.05）が、1 つ下の優先度で OpenAI 公式 API（コスト ×1.00）が供給しています。

- **優先度を優先**：Requesty がリクエストを受け、OpenAI が予備です。
- **コストを優先**：OpenAI がリクエストを受け、Requesty が割高な予備になります。

### 5. 損失が出る VIP 割引

`vip` グループの倍率 **1.05**、決済コスト率 4% では、$1 あたりの純収入は 1.05 × 0.96 = $1.008 です。公式 API 経由ならまだ 0.8% の粗利がありますが、Vercel（×1.03）経由では 2.1%、Requesty 経由では 4.0% の損失です。料金設定カードのグループ表に、`vip` で損失になるチャネルの数が表示されます。倍率を上げるか、割引のコストとして受け入れてください。
