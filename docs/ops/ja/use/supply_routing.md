# 供給によるルーティングを有効にする

供給は、各公開モデルをそれを提供するチャネルへ段階ごとに振り分け、一時停止ルールとフェイルオーバーを備えます。新規インストールでは最初から有効です。以前のリリースからアップグレードしたインストールは設定をそのまま保ちます。`ModelSupplyEnabled` を有効にするまで、リクエストはこれまでどおりチャネルのモデル一覧とモデルマッピングでルーティングされ、供給関連のページは「有効にしたらどうなるか」を表示するだけで、プロバイダーページでチャネルの呼び出し順も並べられません。

自分のデータで移行の内容を確認してから有効にしてください。以下の手順はすべて root ユーザーで行います。サイトにサインインした状態でブラウザーの開発者ツールのコンソールからリクエストを送るため、現在のセッションが使われます。

```js
// 以下の手順で使う関数。
const api = (method, path, body) =>
  fetch(path, { method, headers: { 'Content-Type': 'application/json' }, body: body && JSON.stringify(body) }).then((r) => r.json());
```

## 1. データベースをバックアップする

復元できるバックアップを取ります（SQLite：ゲートウェイを止めてデータベースファイルをコピー。MySQL / PostgreSQL：ダンプを取得）。移行は供給、カタログのモデル、価格を書き込みます。

## 2. ドライラン

```js
const report = (await api('POST', '/api/model_supply/migrate', { dry_run: true })).data;
```

何も書き込まれません。先に進む前にレポートを確認します。

| フィールド | 確認すること |
| --- | --- |
| `supplies_planned` | 作成される供給の数。チャネルとモデルの組ごとに 1 本です。 |
| `new_models`、`new_aliases`、`status_changes` | 追加または公開されるカタログのモデル。チャネルが挙げる名前は公開されるとクライアントから見えます。 |
| `billing_changes`、`price_copies`、`price_conflicts`、`plus_mappings` | 上流名ではなく公開モデルの価格で課金されるようになるリクエスト。価格の競合は先に直してください。 |
| `unresolved_wildcards`、`skipped_entries`、`duplicate_entries` | 供給にならないチャネルのエントリー。チャネル側で直すか、なくなってよいか確認してください。 |
| `policy_gaps` | ターゲットのモデルに供給がなくなるルーティングポリシー。 |
| `routing_differences` | ユーザーグループごとの、到達のしかたが変わるモデル。どれも想定どおりであるべきです。 |

修正するたびにドライランをやり直し、望む変更だけが残るまで繰り返します。

## 3. 移行して有効にする

「プラットフォーム管理 → ゲートウェイ設定 → 割り当て → 供給モードとコスト」で「供給でルーティング」をオンにします。保存する前に、スイッチの下に作成される供給の数と、切り替え後に使える供給がなくなるモデルの数が表示されます。保存すると先に移行し（まだないものだけ）、それから有効になります。API でも同じです。

```js
await api('PUT', '/api/option/', { key: 'ModelSupplyEnabled', value: 'true' });
```

移行される内容は最後のドライランと一致するはずです。

## 4. 確認する

- いくつかの実際の API キーで `GET /v1/models` を呼び、レポートに挙がった差分以外は以前と同じ一覧であることを確認します。
- モデルの「供給」タブのリクエストプレビューで、次のリクエストがどのチャネルに送られるかがわかります。テストリクエストよりプレビューを使ってください。無効なキーでのリクエストは既定の認証情報ルールでチャネルを一時停止させます。
- 有効にしてから最初の 1 時間は、プロバイダーページとログを見守ってください。

## 元に戻す

同じスイッチをオフにして保存するか、次を実行します。

```js
await api('PUT', '/api/option/', { key: 'ModelSupplyEnabled', value: 'false' });
```

ルーティングはすぐにチャネルのモデル一覧に戻ります。供給は残るので、もう一度有効にするときに移行は不要です。その間にチャネルを変更した場合は、念のためドライランをしてください。
