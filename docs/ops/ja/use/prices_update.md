# 価格更新

Modeltaps のモデル価格は価格表にまとめて保存され、管理者が `運営 --> モデル価格` ページで管理します。システムの初回起動時には内蔵の既定価格表で初期化され、その後は手動で管理するか、価格サービスから一括同期するかを選べます。

## 手動での管理

`運営 --> モデル価格` ページでは、モデル価格の新規追加、編集、一括変更、削除を直接行えます。各価格には以下のフィールドが含まれます。

- **モデル名**：リクエスト内の `model` と一致している必要があります。`*` で終わる前方一致にも対応しています（例：`gpt-4o*`）。
- **課金タイプ**：`tokens` は token 単位の課金、`times` は回数単位の課金です。
- **モデルの所属**：すなわち `channel_type` で、「利用可能なモデル」ページでモデルがどのプロバイダーに所属するかを決めます。所属リストは `運営 --> モデル所属` で管理します。価格側の所属 ID は所属リストの ID と一致している必要があり、一致しないとページでプロバイダーごとに正しくグループ化できません。
- **入力 / 出力倍率**：基礎クォータに対する倍率です。回数単位の課金では両方に同じ値を入力します。
- **ロック**：有効にすると、一括同期の「上書き」モードでもその価格は変更されません。人手で確認済みのモデルを保護するのに適しています。
- **追加倍率**：キャッシュの読み書きや音声など、特殊な token の倍率です。
- **ロングコンテキストの段階設定**：入力 token がしきい値を超えた場合、そのリクエスト全体に別の入力／出力倍率を適用します。

## 価格サービスからの一括同期

ページ上の `価格を更新` をクリックし、価格表 JSON を返すアドレスを入力します。取得後はまず「新規モデル」と「価格変更」の比較が表示されるので、内容を確認してから同期方式を選びます。

- **新規追加のみ**：システムに存在しないモデルのみ書き込み、既存の価格は変更しません。
- **上書き**：ロックされていない価格をすべて削除して再作成し、価格表と完全に一致させます。
- **更新のみ**：システムに既に存在するモデルのみ更新し、新規追加は行いません。

::: tip 推奨
本番環境ではまず「新規追加のみ」を使用し、変更部分を 1 件ずつ人手で確認してから反映することを推奨します。一度に上書きして、調整済みの倍率が崩れるのを避けられます。
:::

同じダイアログには、モデルカタログから直結チャネル（OpenAI / Anthropic / Gemini など）の実際の価格を取得して倍率に換算するボタンも用意されています。取得結果も同様に上記の比較プレビューに入り、ロック済みの価格は上書きされません。

### 価格表の JSON フォーマット

価格サービスは価格オブジェクトの配列、または `data` フィールドを持つオブジェクトを返す必要があります（どちらも解析できます）。

```json
[
  {
    "model": "gpt-4o",
    "type": "tokens",
    "channel_type": 1,
    "input": 1.25,
    "output": 5,
    "locked": false,
    "extra_ratios": {
      "cached_read": 0.1,
      "cached_write": 1.25
    },
    "long_context": {
      "threshold": 272000,
      "input_ratio": 2,
      "output_ratio": 1.5
    }
  },
  {
    "model": "mj_imagine",
    "type": "times",
    "channel_type": 34,
    "input": 50,
    "output": 50
  }
]
```

`data` でラップする場合は次のとおりです。

```json
{
  "data": [{ "model": "gpt-4o", "type": "tokens", "channel_type": 1, "input": 1.25, "output": 5 }]
}
```

フィールドの説明：

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `model` | string | モデル名。必須。`*` で終わる前方一致を使用できます |
| `type` | string | 課金タイプ。`tokens` または `times`。必須 |
| `channel_type` | int | モデルの所属 ID。`運営 --> モデル所属` の ID と対応している必要があります |
| `input` | float | 入力倍率。回数単位の課金では 1 回あたりの倍率になります |
| `output` | float | 出力倍率。回数単位の課金では `input` と同じ値を入力します |
| `locked` | bool | ロックするかどうか。ロックされた価格は上書きモードでも変更されません |
| `extra_ratios` | object | 追加倍率。キーは倍率名（`cached_read`、`cached_write` など）、値は倍率です |
| `long_context` | object | ロングコンテキストの段階設定。`threshold`、`input_ratio`、`output_ratio` を含みます。`threshold` が 0 の場合は無効とみなされます |

## 自前の価格サービスを指定する

自分で管理している価格表を使用する場合は、環境変数 `UPDATE_PRICE_SERVICE` で既定のアドレスを指定できます。価格ページの更新ダイアログにはこのアドレスが自動入力されます。

```bash
UPDATE_PRICE_SERVICE=https://prices.your-domain.com/prices.json
```

以下の環境変数と組み合わせると、起動後に定期的な自動同期を行わせることもできます。

- `AUTO_PRICE_UPDATES`：自動更新を有効にするか。
- `AUTO_PRICE_UPDATES_MODE`：自動更新モード。`add` / `overwrite` / `update` / `system`。既定は `system`（プログラム内蔵の価格表で初期化するだけで、価格サービスにはアクセスしません）。
- `AUTO_PRICE_UPDATES_INTERVAL`：自動更新の周期。単位は分。

各変数の詳細な説明は [環境変数](../deployment/env) を参照してください。

::: warning 注意
自動更新は、誰の確認も経ずに価格表を書き換えます。倍率を人手で確認している場合は `AUTO_PRICE_UPDATES_MODE=system` のままにし、重要なモデルには「ロック」を設定したうえで、価格ページから手動で取得し 1 件ずつ確認してから同期することを推奨します。
:::
