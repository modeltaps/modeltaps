# 价格、成本与线路顺序

这一页讲 Modeltaps 怎么决定用户付多少钱、一次请求花你多少成本、请求交给哪条线路，并说明每项设置在哪里配，最后附算例。

## 三个数

| 数 | 是什么 | 谁能看到 |
|---|---|---|
| **目录价** | 模型的官方 API 价，按每百万 token（或按次、按分钟）计 | 所有人，在价格页 |
| **分组倍率** | 每个用户分组在目录价上乘的倍数；`default` 组的倍率就是站点的正常售价 | 用户看到自己所在分组的价格 |
| **渠道成本** | 上游向你收的钱：渠道标价 ×（1 + 渠道费率） | 只有管理员 |

用户付的永远是 **目录价 × 分组倍率**，不随承接请求的渠道变化。渠道成本不会转嫁给用户：它只决定请求交给哪条线路，以及价格闸拦下哪些线路。

一次请求的毛利：

> 目录价 × 分组倍率 ×（1 − 收款成本率）− 渠道成本

**收款成本率**是你自己收款时付出的比例（刷卡手续费、换汇损耗）。不向任何人收取，只用来算扣掉收款成本后的净收入，再拿去和渠道成本比。

## 在哪里配

| 配什么 | 控制台位置 | 设置 / 字段 |
|---|---|---|
| 目录价 | **模型目录** → 某个模型 → 价格；或从价格来源同步 | 模型价格 |
| 站点利润 | **用户 → 用户分组** → `default` 组 → 倍率（1.12 = 比官方价高 12%） | `user_groups.ratio` |
| 折扣组 / 加价组 | **用户 → 用户分组** → 其他分组 | `user_groups.ratio` |
| 收款成本率 | **平台设置 → 计费 → 定价** → 收款成本率 | `PaymentCostPercent` |
| 试算 | 同一张卡片：输入一个默认分组倍率试算（不保存） | — |
| 渠道标价 | **渠道** → 某个渠道 → 价格（从上游同步）；没有价格表的中转：高级 → 成本倍率 | `channel_prices`、`cost_ratio` |
| 渠道费率 | **渠道** → 某个渠道 → 高级 → 渠道费率，或充值记录 | `fee_rate`、`fee_note` |
| 同一档怎么分担 | **平台设置 → 网关 → 分配 → 分流方式与成本** → 同一档内；单个模型在它的「线路」页签里改 | `SupplyModeDefault`、模型的分流方式 |
| 成本与优先级 | 同一张卡片 → 成本与优先级 | `SupplyCostOrder` |
| 档位顺序 | **平台设置 → 网关 → 分配** → 分配策略；手动模型在它的「线路」页签里 | 分配策略、线路优先级 |

上面每项设置的类型、范围和更多示例都在 [设置参考](../settings/index.md) 里。AI 助手可以通过 [管理 MCP](./admin_mcp.md) 查询。

## 渠道费率

渠道费率是渠道商在标价之外另收的比例。多数渠道商在你充值时收，所以：

> 渠道费率 = 实付现金 ÷ 到账额度 − 1

新建渠道先用渠道商公布的费率；没公布的，用结账页上看到的费率：

| 渠道商 | 默认 | 出处 |
|---|---|---|
| Requesty | 5% | 计费文档里的充值服务费 |
| OpenRouter | 5.5% | FAQ 里的购买额度手续费（最低 $0.80；加密货币 5%） |
| Vercel AI Gateway | 3% | Vercel 文档没写，只说手续费由买方承担；2026-11-18 结账页显示 $100 额度收 $3.00 手续费 |
| 官方厂商 API、其他中转 | 0% | — |

在 **渠道 → 高级 → 充值记录** 里录入真实充值：实付了多少现金（含刷卡和换汇费），到账多少额度。之后渠道费率按最近 10 笔充值反推，替换默认值。赠送额度不会让费率变成负数。

## 请求交给哪条线路

1. 先按优先级排（来自分配策略，或手动模型自己的数字）。
2. 设成**成本优先**时，再按成本排（见下文）。
3. 在承接请求的线路之间，看分流方式：**负载均衡**按权重分担，**主备**全部交给权重最高的。

**成本与优先级**（`SupplyCostOrder`）决定成本参不参与：

- **优先级优先**（默认）：成本不参与排序。同一优先级的线路按分流方式分担，便宜的不会把请求全拿走。优先级代表成本以外的考虑（质量、速度、信任的厂商）时选这个。
- **成本优先**：一个模型最便宜的线路先承接请求，不管优先级；更贵的只在所有更便宜的都不可用时才用，成本未知的排最后。有两道门槛，免得便宜但不靠谱的线路只凭价格拿走流量：
  - **最低节省**（`SupplyCostMinSavingPercent`，默认 5%）：要比另一条便宜这么多才排到它前面；差距更小算同价，按优先级和权重分担。
  - **最低成功率**（`SupplyCostMinSuccessPercent`，默认 95%）：本小时和上一小时的成功率低于它的线路，按成本未知处理，排到运行正常的线路后面，恢复后再回到前面。请求不到 20 次的不判断。

  更便宜的托管商也可能更慢或跑的是量化版，切换前先看一下这些线路。

模型的「线路」页签会显示请求实际的尝试顺序；只因为更贵而排在后面的备用线路标着 **更贵，仅兜底**，成功率不够而没能往前排的标着 **成功率低**。

### 网关里的托管商（Vercel AI Gateway）

Vercel AI Gateway 上很多开源模型由多家托管商同时提供，价格和质量各不相同。不加指定时，Vercel 每次按自己的优先级和健康状况挑一家，按那家的价格扣费，所以成本和实际由谁回答都说不准。对这类模型，同步价格时会读出全部托管商，排出一个顺序，每个请求都带上（`providerOptions.gateway.order`）：

1. 厂商自营排第一（例如 Qwen 的阿里、GLM 的智谱）。
2. 其他托管商要先合格：正常服务、近一天可用率不低于**最低成功率**、没有量化、上下文不短于模型标称值、厂商支持缓存时它也支持、价格不低于厂商价的 30%。合格的按价格从低到高排在后面。
3. **成本优先**时，比厂商便宜超过**最低节省**的合格托管商排到厂商前面。厂商暂停服务或可用率不够时排到合格托管商后面。

排在前面的托管商不可用时，Vercel 照样换下一家，请求不会因此失败。渠道成本按顺序里第一家的价格算；价格详情里列出了这个顺序。Vercel 没有列出厂商自营的模型不加指定，按 Vercel 的列表价计成本。顺序随价格同步更新（启动、每天、保存渠道时）。

Vercel 每个请求都会告诉我们实际由哪家托管商服务、扣了多少钱：托管商记在日志详情的**实际托管商**里，扣费记作上游扣费。成本和毛利统计用这笔实际扣费（加渠道费率），不再按价格表估算，所以 Vercel 换到备用托管商时成本也是准的。

## 价格闸

成本高于站点正常售价净收入的线路，每接一个请求都亏钱。判断线是：

> default 组倍率 ×（1 − 收款成本率）

设了利润（判断线高于 1）之后：高于这条线的新线路要等确认；已有的备用线路会关掉等确认；正在承接请求的不关，只通知管理员。**定价**卡片列出每个渠道的保本倍率、会亏的线路和每个用户分组的净收入。

折扣组不参与判断：折扣是你自己的选择。定价卡片仍会显示每个分组下哪些渠道会亏。

## 用上游账单核对价格

价格表可能错在同步发现不了的地方：跟不上厂商调价、促销结束了、中转站在标价上加价。上游自己的账单最准。Modeltaps 每小时把近三天上游实际扣费，和按价格表记下的预期成本（渠道标价，不含费率）做对比：

- **按模型**：用 OpenRouter、Vercel AI Gateway、Cheaper Inference 每个请求返回的费用。
- **按账号**：用填了**上游管理密钥**的 OpenAI、Anthropic、OpenRouter 渠道的每日账单。账单是整个账号的，本站以外也在用这个账号时会显得偏高。

偏差 10% 以上、且至少 10 个请求和 0.10 美元时，渠道上会出现**上游扣费核对**提醒（平台管理 → **提醒**），并发一次价格变动通知。提醒链接到渠道的**统计**页，那里按模型、按天列出两边的金额。

- **扣得比预期多**：请求可能亏钱。改渠道价格、费率或成本倍率。
- **扣得比预期少**：成本设高了，价格闸可能误挡线路。同样去改。

费用重新对上后提醒自动关闭。Gemini 和 Vertex AI 暂时没有可对比的账单。

## 官方调价日程

有些厂商会公布某天起的新价，或者某天结束的优惠价。内置官方价带着这些日期：到了那天价格自动切换（你改过或锁定的不动），管理员收到**官方调价日程**提醒，并立刻重新拉取价格表，不用等到夜里。

优惠价结束而厂商还没公布新价时，提醒会请你去核对厂商价格页（附链接）。价格变了就手动改；提醒会一直保留，直到新版本写入新价。

## 算例

### 1. 比官方价高 12% 卖

把 `default` 组倍率设成 **1.12**，收款成本率 **4%**。每 $1 目录价净收入 1.12 × 0.96 = **$1.0752**。

| 渠道 | 每 $1 目录价的成本 | 毛利 |
|---|---|---|
| 官方 API | $1.00 | 7.5% |
| Vercel AI Gateway（3%） | $1.03 | 4.4% |
| Requesty（5%） | $1.05 | 2.4% |
| OpenRouter（5.5%） | $1.055 | 1.9% |

default 组用户调用一个目录价为每百万 token $3 / $15 的模型，付 $3.36 / $16.80，不管哪个渠道承接。

### 2. 录入一笔 Vercel 充值

你付了 **$103.00**，到账 **$100.00** 额度。新增一条充值记录：实付 103，到账 100。渠道费率变成 3%，费率说明写明是由充值记录算出的。下一笔如果是 $206.40 充 $200，费率变成 (103 + 206.40) ÷ 300 − 1 = 3.13%。

### 3. 同一优先级的两条线路

`glm-5.2` 有 Vercel（成本 ×1.03）和 Requesty（成本 ×1.05）两条线路，优先级相同，负载均衡，权重 3 和 1。

- **优先级优先**：Vercel 承接约 75% 的请求，Requesty 约 25%。
- **成本优先**：两者只差 2%，在最低节省 5% 以内，算同价，照样按 75 / 25 分担。最低节省设成 0 时，请求全部走 Vercel，只有 Vercel 暂停或出错时才走 Requesty。

default 组用户付的价格都一样。

### 4. 成本优先，越过优先级

`gpt-5.1` 有 Requesty（最高优先级，成本 ×1.05）和低一档的折扣中转（成本 ×0.80）。

- **优先级优先**：Requesty 承接请求，中转兜底。
- **成本优先**：中转便宜 24%，承接请求，Requesty 兜底并标为更贵。中转最近两小时失败了 10% 时，成功率低于 95%，Requesty 接回请求；中转恢复后再排回前面。

### 5. 会亏钱的 VIP 折扣

`vip` 组倍率 **1.05**，收款成本率 4%，每 $1 净收入 1.05 × 0.96 = $1.008。走官方 API 仍有 0.8% 毛利；走 Vercel（×1.03）亏 2.1%，走 Requesty 亏 4.0%。定价卡片的分组表会显示 `vip` 下有几个渠道会亏：提高倍率，或者把这部分亏损当作折扣的成本接受下来。
