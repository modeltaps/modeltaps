# API Key 與額度

API Key 就是你調用 Modeltaps 時使用的密鑰。建議按應用、按環境分別建立 API Key，這樣在日誌與用量裏能清楚區分是誰在花錢，出問題時也能單獨停用一把密鑰而不影響其他應用。

## API Key 列表

「API Key」頁面以列表形式展示你的全部 API Key，預設可見的列包括：

| 列 | 含義 |
| --- | --- |
| API Key | 名稱與密鑰末尾幾位（`sk-…Rc6g`）；列表裏從不顯示完整密鑰 |
| 分組 | 該 API Key 使用的渠道分組；未指定時顯示「跟隨用戶」 |
| 過期時間 | 「永不」、剩餘時間或「已過期」 |
| 最近使用 | 上次成功調用的時間，從未調用則顯示「從未使用」 |
| 用量 | 累計已用額度，並附帶「今日」已用 |
| 限額 | 剩餘額度或「未限額」；設了週期時顯示本週期上限與下次重置時間 |
| 狀態 | 開關，可直接啟用 / 停用該 API Key |

右上角的「列設定」可以顯示或隱藏列（例如預設隱藏的「創建時間」）。頂部篩選條支援按 API Key 名稱搜索。

每行的操作菜單提供：編輯、「重設密鑰」、「測試命令」、「接入 OpenClaw」、跳轉到該 API Key 的「用量」和「日誌」以及刪除。

## 密鑰只顯示一次

Modeltaps 不保存你的密鑰本身，只保存它的指紋（雜湊），所以密鑰建立之後無法再次查看：

- 新建 API Key 時，彈窗會顯示一次完整密鑰並提供複製按鈕。請當場複製並妥善保存，例如放進密碼管理器或應用的密鑰設定中。
- 列表和 API Key 詳情裏只顯示遮蓋後的形式（`sk-A****Rc6g`），用來區分不同的密鑰。
- 如果密鑰遺失或疑似洩露，選擇「重設密鑰」（在操作菜單或詳情裏的密鑰一行）。新密鑰同樣只顯示一次，舊密鑰立即失效；名稱、設定、額度和用量都保持不變。在組織中，只有建立該密鑰的成員才能重設它。

此前建立的密鑰照常可用，無需任何改動。

## 把 API Key 交給 Agent

能接第三方 key 的 Agent（OpenClaw、Hermes 等）可以自行完成接入：告訴它「讀 `https://<你的站點>/skill.md` 並接入 Modeltaps」即可。每個 Modeltaps 站點都會按自己的設定提供這份說明，內容包括接口地址、怎樣取得 key、怎樣保管、怎樣驗證以及完成後向你匯報甚麼；`/llms.txt` 是指向它的簡短索引。兩者都不含任何用戶資料或密鑰。

不要把密鑰貼進對話：對話記錄會長期保存、同步，有記憶的 Agent 還可能把它記下來。改用以下兩種方式之一交給 Agent。

### 配對碼

新建 API Key 時，彈窗還會顯示一個**配對碼**（`pair-...`）。把配對碼而不是密鑰交給 Agent：它在 `POST /api/agent/pair` 兌換後自行取得這把密鑰。

- 配對碼 10 分鐘內有效，只能兌換一次，只能換出這一把 API Key；猜錯 5 次即作廢。
- 兌換時這把 API Key 會換上新的密鑰：彈窗裡顯示的密鑰隨即失效，只有 Agent 手上的那份可用。
- API Key 詳情的 **Agent** 一欄顯示它何時被領取、來自哪個 IP、用的甚麼 User-Agent。**新配對碼**可再產生一個（之前未用的隨即作廢）；組織內只有建立此 API Key 的成員才能操作。
- **重設密鑰**會作廢未用的配對碼，Agent 手上的那份也隨即失效。

### 裝置授權

還沒有 key 的 Agent 可以主動申請（OAuth 裝置授權，RFC 8628）：它會給你一個 `https://<你的站點>/device` 連結和一個形如 `BCDF-GHJK` 的代碼。開啟連結並登入，核對請求裡的 Agent 名稱、IP 和 User-Agent，再選好這把 Key 歸誰（你自己或你所在的組織）、額度上限、有效期和模型，按**批准**。Agent 下次查詢時取得新密鑰，頁面上不會顯示它。請求 15 分鐘內有效，只能處理一次；**拒絕**會告知 Agent。

只批准你自己在信任的 Agent 上發起的請求。兩種方式都只會交出 API Key：管理密鑰不能配對也不能申請；產生配對碼和處理申請都只能在登入後的控制台裡進行，不能用任何 key 代辦。

## 密鑰類型：API Key 與管理密鑰

「新建 API Key」先選擇類型：

| 類型 | 能做甚麼 | 不能做甚麼 |
| --- | --- | --- |
| **API Key**（預設） | 調用所有模型介面（`/v1/...`、Claude、Gemini 等中繼介面）；查詢自己的餘額與用量（`/v1/dashboard/billing/subscription`、`/v1/dashboard/billing/usage`）和可用模型（`/v1/models`） | 調用管理介面（`/api/...`）：會被拒絕，返回 `401` 和代碼 `api_key_not_allowed` |
| **管理密鑰 · 唯讀** | 查看餘額、用量、日誌（不含請求與回應正文）和 API Key 列表（密鑰遮蓋），包括你所在組織的；使用 MCP | 調用模型；作任何修改 |
| **管理密鑰 · 讀寫** | 唯讀能做的全部，另可新建、修改、停用、刪除、重設 **API Key** | 調用模型；新建管理密鑰；修改密碼、登入方式、通行密鑰 / 雙重驗證、工作階段或支付；管理後台的任何操作 |

應用和 Agent 日常使用的密鑰請保持為 API Key：即使洩露，損失也止於它的額度。管理密鑰只交給負責管理密鑰的腳本或 Agent，並只放在伺服器端。

管理密鑰：

- 以 `mk-` 開頭，以 `Authorization: Bearer mk-...` 調用管理介面（`/api/...`）和 MCP（`/mcp`）。超出其類型的操作返回 `403` 和代碼 `management_key_forbidden`；用它調用模型介面返回 `401`。
- 必須設定過期時間：預設 90 天，最長一年。過期後返回代碼 `management_key_expired`。
- 與 API Key 一樣只顯示一次，系統只保存指紋。遺失後無法重設，請刪除後重新建立。
- 以你的身份和目前角色行事：在組織裏不會超出你在該組織的角色，它新建的 API Key 歸你所有（成員預算與模型白名單照常生效）。
- 列在 API Key 列表下方的「管理密鑰」區，每行帶類型標籤，可在那裏刪除，刪除後立即失效。只能在登入後的控制台裏新建和刪除，不能用另一把密鑰操作。

管理密鑰屬於個人：切換到組織後，本頁只新建組織 API Key。

### 存取權杖（已棄用）

原來每個帳戶一個的「存取權杖」（設定 → 帳戶安全）由管理密鑰取代。它在下一個版本之前仍按原有權限可用，每個回應都帶 `Deprecation: true` 回應標頭，伺服器日誌也會記錄它的使用。它現在同樣只保存指紋，重新生成後新權杖只顯示一次。它會以「存取權杖（已棄用）」出現在管理密鑰列表中，可在那裏刪除。請在停用之前把腳本改為使用管理密鑰。

## 新建與編輯 API Key

點擊「新建 API Key」打開編輯面板，分為幾個區塊。

### 基本資料

- **名稱**（必填）：日誌與用量分析都按 API Key 名稱聚合，改名後歷史記錄不會跟着改，建議一次定好。
- **永不過期 / 過期時間**：預設永不過期；關掉開關後可以指定一個具體的到期時刻，過期後該 API Key 不再可用。

### 額度與週期

這裏只有一個額度輸入框，含義隨「重置週期」變化：

- **不填額度、不選週期**：不限額。該 API Key 本身不設上限，實際消費仍受帳戶可用額度約束。
- **填了額度、不選週期**：總額限制。累計消費達到該額度後 API Key 即停用。
- **填了額度並選擇週期**（每日 / 每週 / 每月）：額度變成「每週期額度上限」。每到週期邊界的 0 點自動重置，不額外扣減你的帳戶餘額。選擇週期時額度必須大於 0。

面板會提示當前站點用於重置的時區與每週起點（週一或週日）。列表的「限額」列會顯示下次重置時間。

::: warning 額度是兩層
API Key 額度只限制 API Key 自身的最大使用量，真正扣的是帳戶額度。帳戶額度不足時，即使 API Key 未限額也會請求失敗；反過來 API Key 額度用盡時，帳戶再有錢也會被攔下。
:::

### 渠道分組

- **分組**：指定該 API Key 請求走哪個渠道分組，留空則跟隨你的帳戶分組。
- **備用分組**：當主分組不可用時，請求會改走備用分組。

如果分組已被刪除或你無權使用，列表中的分組標籤會以醒目顏色提示。

### 高級設定

- **模型限制**：開啟後可以勾選允許這把 API Key 使用的模型；不勾選任何模型即代表允許全部模型。適合把某個應用限制在少數幾個模型上。編輯已儲存的 API Key 時會顯示「目前可用模型」，已計入渠道分組，組織 API Key 還計入你的成員模型白名單。
- **IP 白名單**：開啟後每行填一個 IP 或 CIDR 段（如 `192.168.1.1`、`10.0.0.0/8`），只有來自這些地址的請求才會被放行。
- **提示快取**：這把 Key 的請求怎樣使用上游提示快取。**自動**（預設）跟隨渠道設定。**開**：不論渠道怎樣設，都給沒帶快取斷點的 Claude 請求加上斷點；反覆發送的長提示詞便宜很多，只發一次的提示詞要多付 25% 的快取寫入費用。**關**：移除請求裡所有 `cache_control` 標記，也不再添加；OpenAI、DeepSeek 等廠商自帶的前綴快取仍會生效。單個請求可以用 `X-Modeltaps-Prompt-Cache` 請求頭（`auto`、`on` 或 `off`）另選，優先於 Key 的設定。
- **心跳設定（實驗性）**：當請求長時間沒有返回數據時，客戶端可能因超時斷開。開啟後，超過你設定的等待秒數仍無響應時，Modeltaps 會每 5 秒發送一次心跳（非流式返回空行，流式返回 `::PING`）以保持連接。等待時間可設 30～90 秒。若你的請求經過中轉程序，不建議開啟。

## 測試 API Key

在操作菜單裏選擇「測試命令」，彈窗會按 OpenAI / Claude / Gemini 三個標籤頁給出可直接運行的 `curl`，其中填好了站點地址和所選模型。模型可以在下拉框中搜索切換。

如果密鑰是你剛在本頁建立或重設的，命令裏已經帶上了它；否則請在彈窗頂部的「API Key」輸入框裏貼上密鑰：它只在本頁面使用，不會儲存。「接入 OpenClaw」同理。

若某個協議提示「該協議下暫無可用模型」，說明當前分組內沒有對應類型的渠道，該協議暫時用不了，可改用 OpenAI 標籤頁測試。

## 停用與刪除

- 列表中的狀態開關可以隨時停用 / 恢復一把 API Key，已停用的 API Key 調用會直接被拒。
- 「刪除」不可恢復，刪除前請確認沒有線上應用還在使用這把密鑰。

## 補充額度

帳戶額度在「充值」頁面補充（入口在側邊欄底部的餘額行），支援在線支付與兌換碼兩種方式；充值記錄請到用戶選單裏的「賬單」頁面、「帳戶流水」標籤查看。詳見 [快速開始](/hk/guide/quickstart) 中的說明。

切換到組織後，這裏管理的是組織 API Key，額度來自組織額度池，還可以按成員設定週期預算，詳見 [組織](/hk/guide/organization)。
