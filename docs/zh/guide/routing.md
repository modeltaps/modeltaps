# 自动路由

自动路由策略是一个可以像普通模型一样调用的模型名，例如 `auto/coder`。网关会读取每个会话的**第一条用户消息**，让一个小的决策模型判断这是哪类请求，再把会话转发给管理员为这类请求指定的模型：简单的活交给便宜、快的模型，难的活交给最强的模型。选定之后整个会话都保持不变。

Claude Code、Codex、Cursor 这类编码 Agent 无法在请求里带路由参数，它们只认一个模型名。策略把路由规则封装进了这个名字。

## 调用策略

把策略名填在 `model` 字段里即可。Chat Completions、Claude Messages、Responses 三种接口都支持，含流式与工具调用；策略也会像普通模型一样出现在 `GET /v1/models` 里。

```bash
curl -X POST https://your-modeltaps-domain.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -d '{
    "model": "auto/coder",
    "messages": [{"role": "user", "content": "给 CLI 加一个 --verbose 参数，并把解析后的参数打到日志"}]
  }'
```

响应里的 `model` 字段是实际应答的模型（站点开启「统一返回请求模型名」时除外）。每个被路由的响应还带一个响应头：

```
X-Modeltaps-Route: policy=auto/coder; label=additive; model=claude-haiku-5-5; confidence=0.90; scoring=logprobs; reason=classified
```

决策模型选中标签时才带 `confidence` 和 `scoring`。`scoring` 说明置信度怎么来的：`logprobs`（该标签的概率）或 `self_reported`（自报），见[打分方式](#打分方式)。

| 原因 | 含义 |
| --- | --- |
| `classified` | 决策模型选中了一个标签，置信度达到策略阈值。 |
| `pinned` | 会话此前已经路由过，这一轮直接沿用，没有重新决策。 |
| `below_threshold` | 选中了标签但置信度不够，由兜底模型应答。 |
| `decision_error` | 决策调用失败、超时或回答了未知标签，由兜底模型应答。 |
| `empty_input` | 首条用户消息没有文本（例如只有图片），由兜底模型应答。 |
| `auxiliary` | 会话还没路由时先到了 Claude Code 的旁路请求（例如生成会话标题），由兜底模型应答，不做决策。 |

对策略的请求不会因为路由而被拒绝：只要决策做不出来，就由兜底模型应答。

## 会话

决策每个会话只做一次，后续轮次直接复用，所以长对话不会中途换模型，上游的提示缓存也能持续命中。会话按以下顺序识别：Claude Code 放在 `metadata.user_id` 里的会话、会话头（`session_id`、`session-id`、`x-session-id`、`x-claude-code-session-id`）、OpenAI 的 `prompt_cache_key`、提示前缀（系统提示加首条用户消息）。要把一段对话稳定在一个模型上，最可靠的做法是带一个固定的会话 id；换一个 id 就是一次新决策。只有真正分类出的结果才会固定：`decision_error` 或 `empty_input` 走兜底后，下一轮会重新分类，决策模型短暂故障不会让新会话一直停在兜底模型上。

会话固定多久由管理员按策略设置（默认一小时）。

## 在编码 Agent 里使用

**Claude Code**

```bash
export ANTHROPIC_BASE_URL=https://your-modeltaps-domain.com/claude
export ANTHROPIC_AUTH_TOKEN=sk-proj-1234567890
export ANTHROPIC_MODEL=auto/coder
claude
```

**Codex CLI**：在 `~/.codex/config.toml` 里指向网关的 provider 下设置模型：

```toml
model = "auto/coder"
```

**Cursor 及其他 OpenAI 兼容客户端**：把网关添加为 OpenAI 兼容端点，自定义模型名填 `auto/coder`。

编码 Agent 会往对话里加自己的上下文：Claude Code 在首条消息里放 `<system-reminder>` 块，Codex 把 `<environment_context>` 和你的 `AGENTS.md` 指令作为单独一条消息放在你的输入前面。网关会去掉这些块，并跳过只含这些内容的消息，决策只看你实际输入的内容。Claude Code 还会用同一个模型发旁路请求，例如生成会话标题；这类请求不带工具，不参与分类：会话路由之前走兜底模型，之后跟随会话。

## 计费与日志

- 被路由的请求按实际应答模型的价格计费，策略本身没有价格。模型目录里策略显示「按目标模型计费」而不是自己的价格。
- 决策调用每个会话向你计费一次，按决策模型的价格，单独记一条标为决策调用的日志。自动打分时，在不返回 logprobs 的渠道上，第一个会话会调两次决策（先 logprobs、再自报），两次都计费。站点管理员可以关闭决策计费。
- 日志里被路由的请求会显示策略、选中的标签、置信度、打分方式（用 logprobs 时还有每个标签的概率）和原因；日志可以按路由策略筛选。

## 配置策略（管理员）

策略在管理后台的 **网关 → 自动路由** 里创建，由以下部分组成：

- **模型名**：客户端调用的名字，如 `auto/coder`。只能用字母、数字和 `. _ / -`，不能与已有模型重名。创建后出现在 `/v1/models` 里，并能像普通模型一样加进令牌和组织白名单。白名单按策略名判定，目标模型不必在调用方的白名单里，因此可以让昂贵或隐藏的模型只经策略可达。
- **决策模型**：给首条消息分类的小而快的对话模型。网关提供的任何对话模型都可以，选一个听指令的。它本身不能是策略。
- **问题与路由**：一句话的问题，加上 2 到 16 个标签，每个标签带简短描述和目标模型。描述请求本身而不是模型，标签要互不重叠：重叠会分散概率、把请求推向兜底。三个模板（编码改动大小、客服分流、推理深度）可作起点。
- **打分方式**：置信度怎么测，见[打分方式](#打分方式)，默认自动。
- **兜底模型与阈值**：决策不可信时由兜底应答，放最稳的模型。阈值（0 到 1，0.5 是不错的起点）和选中标签的置信度比较，调高会让更多模棱两可的请求走兜底。用 logprobs 打分时置信度是概率；自报的置信度只能当排序看。
- **高级**：会话固定多久（0 表示每次都分类）、送给决策模型的首条消息截断长度、决策超时。

**试一试** 标签页只跑决策这一步：粘贴一条首条消息，可并列比较多个决策模型，不转发、不计费、不写会话固定记录。每个结果会显示打分方式，用 logprobs 时还会列出每个标签的概率。启用策略前，用日志里的真实首条消息测一遍。

### 打分方式

决策模型的置信度有两种来源：

- **logprobs**：标签以字母选项的形式给出，模型只回一个字母。网关读取模型对每个字母的输出概率，每个标签都得到一个真实概率，阈值因此名副其实。这需要非推理模型，且渠道会返回 logprobs：OpenAI 兼容接口，如 GPT-4.1、非思考模式的 DeepSeek、自部署的 vLLM。Claude、推理模型和多数聚合网关不返回 logprobs。
- **自报**：模型回答一个标签和它自己给出的置信度数字。任何对话模型都能用，但这个数字没有校准。

| 设置 | 行为 |
| --- | --- |
| 自动（默认） | 用 logprobs。决策模型在某个渠道上不返回时，这次请求改用自报置信度重新决策，该渠道之后 24 小时都用自报。 |
| 仅 logprobs | 用 logprobs；渠道不返回时由兜底模型应答。 |
| 仅自报 | 始终用自报置信度。 |

设置旁的 **检测支持** 会给决策模型发一个很小的测试请求，告诉你它这次被分到的渠道是否返回 logprobs。

决策计费开关在 **系统设置 → 网关行为 → 自动路由**。

## 组织策略

站点管理员可以让组织自己管理策略：在 **系统设置 → 网关行为 → 自动路由** 里打开 **允许组织管理自己的路由策略**，还可以调整每个组织能建的策略数（默认 20 条）。

之后组织的 Owner 和 Admin 会在组织设置里看到 **自动路由**，和通用、成员、预算并列。普通成员看不到这一项，只会在 `/v1/models` 里看到组织的策略，用组织 API Key就能调用。

- 组织的策略只对本组织的 API Key生效，个人令牌和其他组织都看不到。
- 组织策略可以和平台策略同名。本组织的令牌会用组织自己的策略；把它停用后又会回到平台策略。
- 决策模型、目标和兜底只能选组织本来就能调用、且目录里没有隐藏的模型。如果站点之后把某个目标隐藏了，请求会改走兜底（原因 `target_unavailable`）；兜底也被隐藏时，请求返回模型不存在。
- **试一试** 和 **检测支持** 会真实调用决策模型，费用记在组织账上，不计入策略统计。组织侧不能从日志里回放首条消息。
- 策略的新建、修改、启停和删除都会写进组织审计日志。

站点管理员可以在 **网关 → 自动路由** 的 **组织策略** 页签查看所有组织的策略，并在那里停用。
