# API Key 与额度

API Key 就是你调用 Modeltaps 时使用的密钥。建议按应用、按环境分别建立 API Key，这样在日志与用量里能清楚区分是谁在花钱，出问题时也能单独停用一把密钥而不影响其他应用。

## API Key 列表

「API Key」页面以列表形式展示你的全部 API Key，默认可见的列包括：

| 列 | 含义 |
| --- | --- |
| API Key | 名称与密钥末尾几位（`sk-…Rc6g`）；列表里从不显示完整密钥 |
| 分组 | 该 API Key 使用的渠道分组；未指定时显示「跟随用户」 |
| 过期时间 | 「永不」、剩余时间或「已过期」 |
| 最近使用 | 上次成功调用的时间，从未调用则显示「从未使用」 |
| 用量 | 累计已用额度，并附带「今日」已用 |
| 限额 | 剩余额度或「未限额」；设了周期时显示本周期上限与下次重置时间 |
| 状态 | 开关，可直接启用 / 停用该 API Key |

右上角的「列设置」可以显示或隐藏列（例如默认隐藏的「创建时间」）。顶部筛选条支持按 API Key 名称搜索。

每行的操作菜单提供：编辑、「重置密钥」、「测试命令」、「接入 OpenClaw」、跳转到该 API Key 的「用量」和「日志」以及删除。

## 密钥只显示一次

Modeltaps 不保存你的密钥本身，只保存它的指纹（哈希），所以密钥创建之后无法再次查看：

- 新建 API Key 时，弹窗会显示一次完整密钥并提供复制按钮。请当场复制并妥善保存，例如放进密码管理器或应用的密钥配置中。
- 列表和 API Key 详情里只显示遮盖后的形式（`sk-A****Rc6g`），用来区分不同的密钥。
- 如果密钥遗失或疑似泄露，选择「重置密钥」（在操作菜单或详情里的密钥一行）。新密钥同样只显示一次，旧密钥立即失效；名称、设置、额度和用量都保持不变。在组织中，只有创建该密钥的成员才能重置它。

此前创建的密钥照常可用，无需任何改动。

## 把 API Key 交给 Agent

能接第三方 key 的 Agent（OpenClaw、Hermes 等）可以自己完成接入：告诉它「读 `https://<你的站点>/skill.md` 并接入 Modeltaps」即可。每个 Modeltaps 站点都会按自己的设置提供这份说明，内容包括接口地址、怎么拿 key、怎么保管、怎么验证以及完成后向你汇报什么；`/llms.txt` 是指向它的简短索引。两者都不含任何用户信息或密钥。

不要把密钥贴进对话：对话记录会长期保存、同步，带记忆的 Agent 还可能把它记下来。改用下面两种方式之一交给 Agent。

### 配对码

新建 API Key 时，弹窗还会显示一个**配对码**（`pair-...`）。把配对码而不是密钥交给 Agent：它在 `POST /api/agent/pair` 兑换后自己拿到这把密钥。

- 配对码 10 分钟内有效，只能兑换一次，只能换出这一把 API Key；猜错 5 次即作废。
- 兑换时这把 API Key 会换上新的密钥：弹窗里显示的密钥随即失效，只有 Agent 手里的那份可用。
- API Key 详情的 **Agent** 一栏显示它何时被领取、来自哪个 IP、用的什么 User-Agent。**新配对码**可再生成一个（之前未用的随即作废）；组织内只有创建该 API Key 的成员才能操作。
- **重置密钥**会作废未用的配对码，Agent 手里的那份也随即失效。

### 设备授权

还没有 key 的 Agent 可以主动申请（OAuth 设备授权，RFC 8628）：它会给你一个 `https://<你的站点>/device` 链接和一个形如 `BCDF-GHJK` 的代码。打开链接并登录，核对请求里的 Agent 名称、IP 和 User-Agent，再选好这把 Key 归谁（你自己或你所在的组织）、额度上限、有效期和模型，点**批准**。Agent 下次查询时拿到新密钥，页面上不会显示它。请求 15 分钟内有效，只能处理一次；**拒绝**会告知 Agent。

只批准你自己在信任的 Agent 上发起的请求。两种方式都只会交出 API Key：管理密钥不能配对也不能申请；生成配对码和处理申请都只能在登录后的控制台里进行，不能用任何 key 代办。

## 密钥类型：API Key 与管理密钥

「新建 API Key」先选择类型：

| 类型 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| **API Key**（默认） | 调用所有模型接口（`/v1/...`、Claude、Gemini 等中继接口）；查询自己的余额与用量（`/v1/dashboard/billing/subscription`、`/v1/dashboard/billing/usage`）和可用模型（`/v1/models`） | 调用管理接口（`/api/...`）：会被拒绝，返回 `401` 和代码 `api_key_not_allowed` |
| **管理密钥 · 只读** | 查看余额、用量、日志（不含请求与响应正文）和 API Key 列表（密钥打码），包括你所在组织的；使用 MCP | 调用模型；做任何修改 |
| **管理密钥 · 读写** | 只读能做的全部，另可新建、修改、停用、删除、重置 **API Key** | 调用模型；新建管理密钥；修改密码、登录方式、通行密钥 / 二步验证、会话或支付；管理后台的任何操作 |

应用和 Agent 日常使用的密钥请保持为 API Key：即使泄露，损失也止于它的额度。管理密钥只交给负责管理密钥的脚本或 Agent，并只放在服务端。

管理密钥：

- 以 `mk-` 开头，以 `Authorization: Bearer mk-...` 调用管理接口（`/api/...`）和 MCP（`/mcp`）。超出其类型的操作返回 `403` 和代码 `management_key_forbidden`；用它调用模型接口返回 `401`。
- 必须设置过期时间：默认 90 天，最长一年。过期后返回代码 `management_key_expired`。
- 与 API Key 一样只显示一次，系统只保存指纹。遗失后无法重置，请删除后重新创建。
- 以你的身份和当前角色行事：在组织里不会超出你在该组织的角色，它新建的 API Key 归你所有（成员预算与模型白名单照常生效）。
- 列在 API Key 列表下方的「管理密钥」区，每行带类型标签，可在那里删除，删除后立即失效。只能在登录后的控制台里新建和删除，不能用另一把密钥操作。

管理密钥属于个人：切换到组织后，本页只新建组织 API Key。

### 访问令牌（已弃用）

原来每个账户一个的「访问令牌」（设置 → 账户安全）由管理密钥取代。它在下一个版本之前仍按原有权限可用，每个响应都带 `Deprecation: true` 响应头，服务端日志也会记录它的使用。它现在同样只保存指纹，重新生成后新令牌只显示一次。它会以「访问令牌（已弃用）」出现在管理密钥列表中，可在那里删除。请在停用之前把脚本改为使用管理密钥。

## 新建与编辑 API Key

点击「新建 API Key」打开编辑面板，分为几个区块。

### 基本信息

- **名称**（必填）：日志与用量分析都按 API Key 名称聚合，改名后历史记录不会跟着改，建议一次定好。
- **永不过期 / 过期时间**：默认永不过期；关掉开关后可以指定一个具体的到期时刻，过期后该 API Key 不再可用。

### 额度与周期

这里只有一个额度输入框，含义随「重置周期」变化：

- **不填额度、不选周期**：不限额。该 API Key 本身不设上限，实际消费仍受账户可用额度约束。
- **填了额度、不选周期**：总额限制。累计消费达到该额度后 API Key 即停用。
- **填了额度并选择周期**（每日 / 每周 / 每月）：额度变成「每周期额度上限」。每到周期边界的 0 点自动重置，不额外扣减你的账户余额。选择周期时额度必须大于 0。

面板会提示当前站点用于重置的时区与每周起点（周一或周日）。列表的「限额」列会显示下次重置时间。

::: warning 额度是两层
API Key 额度只限制 API Key 自身的最大使用量，真正扣的是账户额度。账户额度不足时，即使 API Key 未限额也会请求失败；反过来 API Key 额度用尽时，账户再有钱也会被拦下。
:::

### 渠道分组

- **分组**：指定该 API Key 请求走哪个渠道分组，留空则跟随你的账号分组。
- **备用分组**：当主分组不可用时，请求会改走备用分组。

如果分组已被删除或你无权使用，列表中的分组标签会以醒目颜色提示。

### 高级设置

- **模型限制**：开启后可以勾选允许这把 API Key 使用的模型；不勾选任何模型即代表允许全部模型。适合把某个应用限制在少数几个模型上。编辑已保存的 API Key 时会显示「当前可用模型」，已计入渠道分组，组织 API Key 还计入你的成员模型白名单。
- **IP 白名单**：开启后每行填一个 IP 或 CIDR 段（如 `192.168.1.1`、`10.0.0.0/8`），只有来自这些地址的请求才会被放行。
- **提示缓存**：这把 Key 的请求怎么使用上游提示缓存。**自动**（默认）跟随渠道设置。**开**：不论渠道怎么设，都给没带缓存断点的 Claude 请求加上断点；反复发送的长提示词便宜很多，只发一次的提示词要多付 25% 的缓存写入费用。**关**：去掉请求里所有 `cache_control` 标记，也不再添加；OpenAI、DeepSeek 等厂商自带的前缀缓存仍会生效。单个请求可以用 `X-Modeltaps-Prompt-Cache` 请求头（`auto`、`on` 或 `off`）另选，优先于 Key 的设置。
- **心跳设置（实验性）**：当请求长时间没有返回数据时，客户端可能因超时断开。开启后，超过你设置的等待秒数仍无响应时，Modeltaps 会每 5 秒发送一次心跳（非流式返回空行，流式返回 `::PING`）以保持连接。等待时间可设 30～90 秒。若你的请求经过中转程序，不建议开启。

## 测试 API Key

在操作菜单里选择「测试命令」，弹窗会按 OpenAI / Claude / Gemini 三个标签页给出可直接运行的 `curl`，其中填好了站点地址和所选模型。模型可以在下拉框中搜索切换。

如果密钥是你刚在本页创建或重置的，命令里已经带上了它；否则请在弹窗顶部的「API Key」输入框里粘贴密钥：它只在本页面使用，不会保存。「接入 OpenClaw」同理。

若某个协议提示「该协议下暂无可用模型」，说明当前分组内没有对应类型的渠道，该协议暂时用不了，可改用 OpenAI 标签页测试。

## 停用与删除

- 列表中的状态开关可以随时停用 / 恢复一把 API Key，已停用的 API Key 调用会直接被拒。
- 「删除」不可恢复，删除前请确认没有线上应用还在使用这把密钥。

## 补充额度

账户额度在「充值」页面补充（入口在侧边栏底部的余额行），支持在线支付与兑换码两种方式；充值记录请到用户菜单里的「账单」页面、「账户流水」标签查看。详见 [快速开始](/zh/guide/quickstart) 中的说明。

切换到组织后，这里管理的是组织 API Key，额度来自组织额度池，还可以按成员设置周期预算，详见 [组织](/zh/guide/organization)。
