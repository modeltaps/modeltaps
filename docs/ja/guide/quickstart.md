# クイックスタート

このページでは数分で最初の呼び出しを完了します。ログイン → API キーの新規作成 → テストコマンドをコピーして実行 → アドレスとキーを自分のアプリケーションに設定、という流れです。

## 1. ログインしてダッシュボードを確認する

アカウントでログインすると、まず「ダッシュボード」が表示されます。ここでは次の情報を確認できます。

- 利用可能なクォータ、本日のリクエスト数、本日の消費額、本日の Token 量
- 直近 7 日間の利用傾向とモデルの利用状況
- 「現在利用可能なモデル」、つまり現在のグループで呼び出せるモデルの一覧
- 「クイックスタート」カード。チャットクライアントのボタンをクリックすると、システムがチャット専用の API キーを自動作成し、そのキーを渡した状態でクライアントを開きます。まず使い心地を確かめたいときに便利です。

サイドバー下部の残高行に利用可能なクォータが表示され、クリックすると「チャージ」ページを開けます。所属グループによって、ルーティングできるチャネルと 1 分あたりのリクエスト数の上限が決まります。

## 2. API キーを新規作成する

本格的に接続する場合は「API キー」ページで自分で API キーを作成してください。

1. 「API キーを新規作成」をクリックします。
2. 「名称」（必須）を入力します。後からログや利用状況でアプリケーションを区別するために使います。
3. 「有効期限」は既定で「無期限」です。期限を設けたい場合はスイッチをオフにして具体的な日時を選択します。
4. 「クォータ」を空欄にすると上限なしです。数値を入力すると、その API キーで消費できるクォータの上限になります。
5. 「グループ」でこの API キーが使用するチャネルグループを指定できます。空欄の場合はアカウントの既定グループを使用します。
6. 送信します。

より細かいクォータ、周期リセット、モデル制限、IP ホワイトリストなどの設定は [API キーとクォータ](/ja/guide/tokens) を参照してください。

::: tip API キーのクォータとアカウントのクォータは別物です
API キーのクォータは、そのキー自身の最大利用量のみを制限します。実際の課金は引き続きアカウントの利用可能クォータに制約されます。どちらか一方でも不足するとリクエストは拒否されます。
:::

## 3. テストコマンドで確認する

「API キー」一覧で作成した API キーを見つけ、「テストコマンド」を開きます。ダイアログでは OpenAI / Claude / Gemini のタブでプロトコルを切り替え、モデルを選択できます。Modeltaps が実際のキー、サイトアドレス、モデル名を組み合わせて、そのまま実行できる `curl` コマンドを生成します。「コマンドをコピー」をクリックしてターミナルに貼り付けて実行してください。

いずれかのプロトコルのタブで利用可能なモデルがないと表示される場合は、現在のグループにその種類のチャネルが存在しないということです。「OpenAI」タブに戻ってテストしてください。

## 4. 自分のアプリケーションに接続する

API キーを取得したら、アプリケーション側で次の 2 点を設定します。

- API アドレス（Base URL）を Modeltaps のサイトアドレスに向ける
- API Key を Modeltaps が生成した API キー（`sk-` で始まる文字列）に差し替える

3 種類のプロトコルの具体的なアドレスとリクエスト例は [API 接続](/ja/guide/api) を参照してください。

## 5. チャージと交換コード

クォータを補充したいときは、サイドバー下部の残高行から「チャージ」ページを開きます。

- 「オンラインチャージ」：チャージ金額を入力し、支払い方法を選んで決済します。割引後の価格、手数料、実際の支払い金額が表示されます。
- 「交換コードでチャージ」：受け取った交換コードを入力欄に貼り付け、「交換」をクリックすると入金されます。

チャージや招待などの会計記録はリクエストログには含まれません。サイドバー下部のユーザーメニューから「請求」ページを開き、「アカウント明細」タブで確認してください。

同僚と 1 つのクレジットプールを共用する場合は、チャージとクォータを組織でまとめて管理できます。詳しくは [組織](/ja/guide/organization) を参照してください。
