# 料金と価格

このページでは、Modeltaps が 1 回のリクエストの費用をどのように計算するか、および価格と請求明細をどのページで確認できるかを説明します。

## クォータと金額

残高は「クォータ」で記帳され、サイトは固定の比率でクォータを金額に換算して表示します：**500,000 クォータ = $1**。

画面上の金額は通常そのまま米ドルで表示されます。サイトが通貨表示を無効にしている場合は、元のクォータの数値が表示されます。価格ページの単価は「$ / 1K tokens」と「$ / 1M tokens」を切り替えて表示できます。

## 価格を確認できる場所

「利用可能なモデル」ページを開くと、すべてのモデルの入力価格と出力価格を確認できます。

- **グループ**：右上でグループを切り替えると、グループ倍率に応じて価格が変わります。倍率は `x1`、`x0.5` のようなバッジで示され、倍率が 0 のモデルは「無料」と表示されます。
- **利用可能なもののみ表示**：既定で有効になっており、現在のグループで呼び出せるモデルのみが一覧されます。
- **種類**：「従量課金」と「回数課金」の 2 つの課金方式を区別します。
- **単位**：「表示」メニューで K / M の単位を切り替えます。
- **詳細を表示**：行末の目のアイコンをクリックすると、そのモデルの各グループでの価格に加え、キャッシュ、音声、推論などの拡張倍率を確認できます。

あるモデルに「価格未設定」と表示される場合、サイトがまだそのモデルの価格を設定していないため、呼び出しが直接拒否される可能性があります。

## 従量課金（tokens）

大多数の対話モデルとテキストモデルは token 単位で課金され、入力と出力はそれぞれ独立して計算されます。

> 今回の費用 = 入力 token 数 × 入力単価 + 出力 token 数 × 出力単価

ここでの単価は価格ページに表示されている価格、つまり**モデル単価 × グループ倍率**です。入力と出力はそれぞれの価格を使用し、これ以外の係数が掛かることはありません。

## 回数課金（times）

画像生成や音楽などのモデルは回数単位で課金されます。1 回の呼び出しが成功して結果が返れば、消費した token 数にかかわらず固定の 1 回あたりの価格が課金されます。この種のモデルは価格ページの「種類」列に「回数課金」と表示されます。

## 拡張倍率

一部の利用量は特殊な種類の token に該当します。たとえばキャッシュにヒットした入力、音声、推論過程などです。これらはそれぞれの倍率で換算されたうえで、入力側または出力側に計上されます。

| 名称 | 計上側 | 意味 |
| --- | --- | --- |
| `cached_tokens` | 入力 | プロンプトキャッシュにヒットした入力 token |
| `cached_write_tokens` | 入力 | キャッシュへの書き込み（有効期間 5 分） |
| `cached_write_1h_tokens` | 入力 | キャッシュへの書き込み（有効期間 1 時間） |
| `cached_read_tokens` | 入力 | キャッシュからの読み取り |
| `openai_cache_write_tokens` | 入力 | OpenAI のキャッシュ書き込み |
| `input_audio_tokens` | 入力 | 音声入力 |
| `input_text_tokens` | 入力 | テキスト入力 |
| `input_image_tokens` | 入力 | 画像入力 |
| `output_audio_tokens` | 出力 | 音声出力 |
| `output_image_tokens` | 出力 | 画像出力 |
| `output_text_tokens` | 出力 | テキスト出力 |
| `reasoning_tokens` | 出力 | 推論過程で消費した token |

倍率の意味は単純です。**倍率 1 は通常の token と同価格、1 より大きければ高く、1 より小さければ安くなります**。たとえばキャッシュ読み取りの既定倍率は 0.1 で、キャッシュにヒットした入力部分は 10 分の 1 の価格で計算されます。有効期間 1 時間のキャッシュ書き込みの既定倍率は 2 です。

各モデルの実際の倍率は「詳細を表示」に表示される値が基準です。個別に設定されていない種類は通常の token として計算されます。

## ロングコンテキストの段階制

一部のモデルにはロングコンテキストの段階制が設定されています。今回のリクエストの入力 token が設定されたしきい値を超えると、そのリクエスト全体の入力価格と出力価格にそれぞれ対応する段階倍率が掛かります。しきい値を超えない場合、価格は変わりません。

## 事前差し引きと精算

リクエストを発行する際、システムは入力 token に基づいてクォータの一部を先に差し引きます。リクエスト終了後に実際の使用量で精算し、過不足を調整します。そのため、次のようになります。

- 残高または API キーのクォータが不足している場合、リクエストは発行前に拒否されます。
- ストリーミングリクエストの途中でクォータを使い切ると、接続が切断されます。
- ログに表示される費用は精算後の最終金額です。

## 請求明細を確認する

- 「利用状況」ページ：時間、モデル、API キー、アプリケーションの各軸で消費金額、Token 量、リクエスト数を確認できます。
- 「ログ」ページ：リクエスト単位の費用を確認できます。レコードの詳細を展開すると、今回の実際の入力価格、出力価格、グループ倍率、元の課金額と最終的な費用に加え、キャッシュや推論など各種 token の内訳を確認できます。
- 「請求」ページの「アカウント明細」タブ（サイドバー下部のユーザーメニューから「請求」を開きます）：チャージ、交換、システム調整などの会計記録です。これらはリクエストログには含まれません。

交換コードには用途が限定されている場合があります。「個人のみ」のコードは個人アカウントにしか入金できず、「組織のみ」のコードは組織コンテキストで組織クレジットプールにのみ入金できます。誤ったコンテキストで交換すると拒否され、コードはそのまま使用可能なまま残ります。詳しくは [組織](/ja/guide/organization) を参照してください。
