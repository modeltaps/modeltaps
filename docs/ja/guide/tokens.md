# API キーとクォータ

API キーは Modeltaps を呼び出すときに使用する認証情報です。アプリケーションごと、環境ごとに API キーを分けて作成すると、ログや利用状況で「誰が使っているか」を明確に区別でき、問題が起きたときも他のアプリケーションに影響を与えずにそのキーだけを停止できます。

## API キー一覧

「API キー」ページでは所有するすべての API キーが一覧表示されます。既定で表示される列は次のとおりです。

| 列 | 意味 |
| --- | --- |
| API キー | 名称とキーの末尾数文字（`sk-…Rc6g`）。完全なキーが一覧に表示されることはありません |
| グループ | その API キーが使用するチャネルグループ。未指定の場合は「ユーザーに従う」と表示されます |
| 有効期限 | 「無期限」、残り時間、または「期限切れ」 |
| 最終使用 | 前回呼び出しに成功した時刻。一度も呼び出していない場合は「未使用」と表示されます |
| 利用量 | 累計の使用クォータと、あわせて「本日」の使用量 |
| 上限 | 残りクォータまたは「上限なし」。周期を設定している場合は当該周期の上限と次回リセット時刻を表示します |
| 状態 | スイッチ。その API キーを直接有効化 / 停止できます |

右上の「列設定」で列の表示 / 非表示を切り替えられます（例：既定で非表示の「作成日時」）。上部のフィルターバーでは API キー名称で検索できます。

各行の操作メニューからは、編集、「キーを再発行」、「テストコマンド」、「OpenClaw に接続」、その API キーの「利用状況」と「ログ」へのジャンプ、削除を実行できます。

## キーが表示されるのは一度だけ

Modeltaps はキーそのものを保存せず、キーの指紋（ハッシュ）だけを保存します。そのため、作成後にキーを再表示することはできません。

- API キーを作成すると、ダイアログに完全なキーが一度だけ表示され、コピーボタンが付きます。その場でコピーし、パスワードマネージャーやアプリケーションのシークレット設定など安全な場所に保管してください。
- 一覧と API キーの詳細では、キーを区別できるようにマスクした形（`sk-A****Rc6g`）だけを表示します。
- キーを紛失した場合や漏えいが疑われる場合は、「キーを再発行」（操作メニュー、または詳細のキーの行）を選択します。新しいキーも一度だけ表示され、古いキーはただちに使えなくなります。名称、設定、上限、使用量はそのまま残ります。組織では、キーを作成したメンバーだけが再発行できます。

この変更より前に作成したキーは、そのまま使い続けられます。

## API キーをエージェントに渡す

サードパーティのキーを扱えるエージェント（OpenClaw、Hermes など）は自分で接続を設定できます。「`https://<あなたのサイト>/skill.md` を読んで Modeltaps を設定して」と伝えてください。このファイルは各 Modeltaps サイトが自身の設定から提供するもので、ベース URL、キーの受け取り方、保管方法、確認方法、完了後に報告する内容を説明しています。`/llms.txt` はそこを指す短い索引です。どちらにもユーザー情報やキーは含まれません。

キーをチャットに貼り付けないでください。会話は保存・同期され、記憶を持つエージェントはキーを書き留めることがあります。代わりに次のどちらかの方法でエージェントに渡してください。

### ペアリングコード

API キーを作成すると、ダイアログに**ペアリングコード**（`pair-...`）も表示されます。キーの代わりにこのコードをエージェントに渡すと、エージェントは `POST /api/agent/pair` でコードを引き換えてキーを自分で受け取ります。

- ペアリングコードは 10 分間有効で、1 回だけ、そのキーにだけ使えます。5 回間違えると無効になります。
- 引き換えるとキーには新しいシークレットが発行されます。ダイアログに表示されたキーは使えなくなり、有効なのはエージェントの手元のものだけです。
- キー詳細の**エージェント**欄には、受け取られた日時、IP アドレス、User-Agent が表示されます。**新しいペアリングコード**で別のコードを発行できます（未使用の以前のコードは無効になります）。組織では、キーを作成したメンバーだけが操作できます。
- **キーを再発行**すると未使用のペアリングコードは無効になり、エージェントの手元のキーも使えなくなります。

### デバイス認可

キーを持たないエージェントは自分からキーを求めることができます（OAuth デバイスフロー、RFC 8628）。エージェントは `https://<あなたのサイト>/device` へのリンクと `BCDF-GHJK` のようなコードを示します。リンクを開いてサインインし、リクエストに表示されたエージェント名、IP アドレス、User-Agent を確認してから、キーの所属（個人または所属する組織）、利用上限、有効期限、モデルを選んで**承認**してください。エージェントは次の確認時に新しいキーを受け取り、ページには表示されません。リクエストは 15 分間有効で、1 回だけ応答できます。**拒否**するとエージェントに伝わります。

信頼できるエージェントで自分が開始したリクエストだけを承認してください。どちらの方法でも渡されるのは API キーだけです。管理キーはペアリングもリクエストもできず、コードの発行やリクエストへの応答はサインインしたコンソールからのみ行え、キーでは代行できません。

## キーの種類：API キーと管理キー

「API キーを新規作成」では、最初に種類を選びます。

| 種類 | できること | できないこと |
| --- | --- | --- |
| **API キー**（既定） | すべてのモデル API（`/v1/...`、Claude、Gemini などの中継エンドポイント）の呼び出し、自分の残高と使用量（`/v1/dashboard/billing/subscription`、`/v1/dashboard/billing/usage`）と利用可能なモデル（`/v1/models`）の確認 | 管理 API（`/api/...`）の呼び出し：`401` とコード `api_key_not_allowed` で拒否されます |
| **管理キー・読み取り専用** | 残高、使用量、ログ（リクエスト・レスポンス本文を除く）、API キー一覧（キーはマスク）の確認（所属する組織のものを含む）、MCP の利用 | モデルの呼び出し、あらゆる変更 |
| **管理キー・読み書き** | 読み取り専用でできることに加え、**API キー**の作成・編集・無効化・削除・再発行 | モデルの呼び出し、管理キーの作成、パスワード・ログイン方法・パスキー / 二段階認証・セッション・支払いの変更、管理コンソールの操作 |

アプリケーションやエージェントが日常的に使うキーは API キーのままにしてください。漏えいしても被害はそのキーの上限までで済みます。管理キーはキーを管理するスクリプトやエージェントにだけ渡し、サーバー側にのみ置いてください。

管理キーについて:

- `mk-` で始まり、`Authorization: Bearer mk-...` として管理 API（`/api/...`）と MCP（`/mcp`）に送ります。種類で許可されていない操作は `403` とコード `management_key_forbidden` で拒否され、モデル API に使うと `401` になります。
- 有効期限が必須です。既定は 90 日、最長 1 年です。期限切れのキーはコード `management_key_expired` で拒否されます。
- API キーと同じく一度だけ表示され、保存されるのは指紋だけです。紛失したキーは再発行できないため、削除して作り直してください。
- あなたとして、現在のロールで動作します。組織内ではその組織でのロールを超えることはなく、作成した API キーはあなたのものになります（メンバー予算とモデル許可リストが適用されます）。
- API キー一覧の下の「管理キー」欄に種類のタグ付きで表示され、そこから削除できます。削除するとすぐに使えなくなります。作成と削除はログインしたコンソールからのみ行え、別のキーでは操作できません。

管理キーは個人のものです。組織に切り替えている間、このページでは組織の API キーだけを作成します。

### アクセストークン（非推奨）

これまでのアカウントごとの「アクセストークン」（設定 → アカウントのセキュリティ）は管理キーに置き換えられます。次のリリースまでは従来の権限のまま使え、各レスポンスに `Deprecation: true` ヘッダーが付き、サーバーログにも使用が記録されます。現在は指紋だけを保存するため、再生成した新しいトークンは一度だけ表示されます。管理キー一覧には「アクセストークン（非推奨）」として表示され、そこから削除できます。使えなくなる前にスクリプトを管理キーへ移行してください。

## API キーの新規作成と編集

「API キーを新規作成」をクリックすると編集パネルが開きます。いくつかのブロックに分かれています。

### 基本情報

- **名称**（必須）：ログと利用状況分析はいずれも API キー名称で集計されます。名称を変更しても過去の記録は変わらないため、最初に決めておくことをおすすめします。
- **無期限 / 有効期限**：既定では無期限です。スイッチをオフにすると具体的な期限を指定でき、期限を過ぎるとその API キーは使用できなくなります。

### クォータと周期

クォータの入力欄は 1 つだけで、その意味は「リセット周期」によって変わります。

- **クォータ未入力・周期未選択**：上限なし。API キー自体には上限を設けませんが、実際の消費は引き続きアカウントの利用可能クォータに制約されます。
- **クォータ入力・周期未選択**：総額の制限。累計消費がそのクォータに達すると API キーは停止されます。
- **クォータ入力・周期を選択**（毎日 / 毎週 / 毎月）：クォータは「周期ごとのクォータ上限」になります。周期の境界の 0 時に自動でリセットされ、アカウント残高から追加で差し引かれることはありません。周期を選択する場合、クォータは 0 より大きい必要があります。

パネルには、リセットに使用されるサイトのタイムゾーンと週の開始曜日（月曜または日曜）が表示されます。一覧の「上限」列には次回リセット時刻が表示されます。

::: warning クォータは 2 層構造です
API キーのクォータは API キー自身の最大使用量のみを制限し、実際に差し引かれるのはアカウントのクォータです。アカウントのクォータが不足していると、API キーが上限なしでもリクエストは失敗します。逆に API キーのクォータを使い切ると、アカウントに残高があっても遮断されます。
:::

### チャネルグループ

- **グループ**：その API キーのリクエストがどのチャネルグループを通るかを指定します。空欄の場合はアカウントのグループに従います。
- **予備グループ**：メイングループが利用できない場合、リクエストは予備グループを経由します。

グループが削除済み、または使用権限がない場合、一覧のグループラベルが目立つ色で警告表示されます。

### 詳細設定

- **モデル制限**：有効にすると、その API キーで使用を許可するモデルを選択できます。1 つも選択しない場合はすべてのモデルを許可する意味になります。特定のアプリケーションを数個のモデルに限定したい場合に便利です。保存済みの API キーを編集すると「現在利用可能なモデル」が表示され、チャネルグループと、組織の API キーではメンバーのモデル許可リストも反映されます。
- **IP ホワイトリスト**：有効にすると 1 行に 1 つの IP または CIDR（例：`192.168.1.1`、`10.0.0.0/8`）を入力でき、これらのアドレスからのリクエストのみが許可されます。
- **プロンプトキャッシュ**：このキーのリクエストが上流のプロンプトキャッシュをどう使うか。**自動**（既定）はチャネルの設定に従います。**オン**はチャネルの設定にかかわらず、キャッシュブレークポイントのない Claude リクエストに付けます。繰り返し送る長いプロンプトは大幅に安くなり、一度だけ送るプロンプトはキャッシュ書き込みの分 25% 高くなります。**オフ**はクライアント自身が付けたものも含め、リクエストの `cache_control` マーカーをすべて取り除き、追加もしません。OpenAI や DeepSeek など、プロバイダー独自のプレフィックスキャッシュは引き続き働きます。リクエストごとに `X-Modeltaps-Prompt-Cache` ヘッダー（`auto`、`on`、`off`）で別の設定を選べ、キーの設定より優先されます。
- **ハートビート設定（実験的）**：リクエストが長時間データを返さない場合、クライアントがタイムアウトで切断されることがあります。有効にすると、設定した待機秒数を超えても応答がないときに、Modeltaps が 5 秒ごとにハートビートを送信して接続を維持します（非ストリームでは空行、ストリームでは `::PING` を返します）。待機時間は 30〜90 秒の範囲で設定できます。リクエストが中継プログラムを経由する場合、有効化は推奨されません。

## API キーのテスト

操作メニューから「テストコマンド」を選択すると、OpenAI / Claude / Gemini の 3 つのタブで、サイトアドレスと選択したモデルを入力済みの、そのまま実行できる `curl` が表示されます。モデルはドロップダウンで検索して切り替えられます。

このページで作成または再発行した直後のキーなら、コマンドにはすでにキーが入っています。それ以外の場合は、ダイアログ上部の「API キー」欄にキーを貼り付けてください。キーはこのページでのみ使われ、保存されません。「OpenClaw に接続」も同様です。

いずれかのプロトコルで「このプロトコルで利用できるモデルがありません」と表示される場合は、現在のグループに対応する種類のチャネルが存在せず、そのプロトコルは当面利用できません。OpenAI タブでテストしてください。

## 停止と削除

- 一覧の状態スイッチで API キーをいつでも停止 / 復帰できます。停止した API キーでの呼び出しは直接拒否されます。
- 「削除」は元に戻せません。削除する前に、そのキーを使用している本番アプリケーションがないことを確認してください。

## クォータの補充

アカウントのクォータは「チャージ」ページ（サイドバー下部の残高行から開けます）で補充でき、オンライン決済と交換コードの 2 つの方法に対応しています。チャージ記録はユーザーメニューの「請求」ページ、「アカウント明細」タブで確認してください。詳しくは [クイックスタート](/ja/guide/quickstart) の説明を参照してください。

組織に切り替えると、このページで管理するのは組織 API キーになります。クォータは組織のクレジットプールから引かれ、メンバーごとに周期予算を設定することもできます。詳しくは [組織](/ja/guide/organization) を参照してください。
