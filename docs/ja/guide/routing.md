# 自動ルーティング

自動ルーティングポリシーは、`auto/coder` のように通常のモデルと同じ方法で呼び出せるモデル名です。ゲートウェイは各会話の**最初のユーザーメッセージ**を読み、小さな判定モデルにどの種類のリクエストかを尋ね、管理者がその種類に割り当てたモデルへ会話を転送します。簡単な作業は安くて速いモデルへ、難しい作業は最も強いモデルへ送られます。選択はセッションの間ずっと保持されます。

Claude Code、Codex、Cursor などのコーディングエージェントはリクエストにルーティング用のパラメーターを付けられず、モデル名しか知りません。ポリシーはルーティングをその名前の中に詰め込みます。

## ポリシーを呼び出す

`model` フィールドにポリシー名を指定します。Chat Completions、Claude Messages、Responses API でストリーミングやツール呼び出しを含めて動作し、`GET /v1/models` にも通常のモデルと同様に表示されます。

```bash
curl -X POST https://your-modeltaps-domain.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -d '{
    "model": "auto/coder",
    "messages": [{"role": "user", "content": "CLI に --verbose フラグを追加し、解析した引数をログに出して"}]
  }'
```

レスポンスの `model` フィールドは実際に応答したモデルです（サイトがリクエストされた名前をそのまま返す設定になっている場合を除く）。ルーティングされたレスポンスには次のヘッダーも付きます。

```
X-Modeltaps-Route: policy=auto/coder; label=additive; model=claude-haiku-5-5; confidence=0.90; scoring=logprobs; reason=classified
```

`confidence` と `scoring` は判定モデルがラベルを選んだときだけ付きます。`scoring` は確信度の測り方を示します: `logprobs`（そのラベルの確率）または `self_reported`（自己申告）。[スコアリング](#スコアリング)を参照してください。

| reason | 意味 |
| --- | --- |
| `classified` | 判定モデルがポリシーのしきい値以上の確信度でラベルを選びました。 |
| `pinned` | すでにルーティング済みのセッションの後続ターンで、新しい判定は行われていません。 |
| `below_threshold` | ラベルは選ばれたものの確信度が足りず、フォールバックモデルが応答しました。 |
| `decision_error` | 判定呼び出しが失敗・タイムアウトした、または未知のラベルを返したため、フォールバックモデルが応答しました。 |
| `empty_input` | 最初のユーザーメッセージにテキストがなく（画像のみなど）、フォールバックモデルが応答しました。 |
| `auxiliary` | セッションのルーティング前に Claude Code の補助リクエスト（セッションタイトルの生成など）が届いたため、判定は行わずフォールバックモデルが応答しました。 |

ポリシーへのリクエストがルーティングを理由に拒否されることはありません。判定ができないときは常にフォールバックモデルが応答します。

## セッション

判定はセッションごとに 1 回行われ、後続のターンで再利用されます。そのため長い会話の途中でモデルが切り替わることはなく、上流のプロンプトキャッシュも効き続けます。セッションは次の順で識別されます: `metadata.user_id` にある Claude Code のセッション、セッションヘッダー（`session_id`、`session-id`、`x-session-id`、`x-claude-code-session-id`）、OpenAI の `prompt_cache_key`、プロンプト接頭辞（システムプロンプトと最初のユーザーメッセージ）。会話を 1 つのモデルに固定する最も確実な方法は、安定したセッション ID を送ることです。新しい ID は新しい判定を開始します。固定されるのは実際に分類できた結果だけです。`decision_error` や `empty_input` でフォールバックした場合は次のターンで改めて分類するので、判定モデルが一時的に落ちても新しいセッションがフォールバックモデルに留まり続けることはありません。

セッションを固定する時間はポリシーごとに管理者が設定します（既定は 1 時間）。

## コーディングエージェントで使う

**Claude Code**

```bash
export ANTHROPIC_BASE_URL=https://your-modeltaps-domain.com/claude
export ANTHROPIC_AUTH_TOKEN=sk-proj-1234567890
export ANTHROPIC_MODEL=auto/coder
claude
```

**Codex CLI** — `~/.codex/config.toml` でゲートウェイを指すプロバイダーにモデルを設定します。

```toml
model = "auto/coder"
```

**Cursor などの OpenAI 互換クライアント** — ゲートウェイを OpenAI 互換エンドポイントとして追加し、カスタムモデル名に `auto/coder` を入力します。

コーディングエージェントは会話に独自のコンテキストを加えます。Claude Code は最初のメッセージに `<system-reminder>` ブロックを入れ、Codex は `<environment_context>` と `AGENTS.md` の指示を入力より前の別メッセージとして送ります。ゲートウェイはこれらのブロックを取り除き、それしか含まないメッセージは飛ばすので、判定は実際に入力した内容に基づきます。Claude Code は同じモデルでセッションタイトルの生成などの補助リクエストも送ります。これらはツールを持たず分類されません。セッションのルーティング前はフォールバックモデルへ、その後はセッションに従います。

## 課金とログ

- ルーティングされたリクエストは、ポリシー自体の価格ではなく、実際に応答したモデルの価格で課金されます。モデルカタログではポリシーに価格の代わりに「ターゲットモデルで課金」と表示されます。
- 判定呼び出しはセッションごとに 1 回、判定モデルの価格で課金され、判定呼び出しとして印の付いた独立したログになります。自動スコアリングでは、logprobs を返さないチャネルでの最初のセッションは判定を 2 回呼び出し（logprobs、続いて自己申告）、両方とも課金されます。サイト管理者は判定の課金をオフにできます。
- ログでは、ルーティングされたリクエストにポリシー、選ばれたラベル、確信度、スコアリング方法（logprobs のときは各ラベルの確率も）、理由が表示され、ルーティングポリシーでログを絞り込めます。

## ポリシーの設定（管理者）

ポリシーはコンソールの **ゲートウェイ → 自動ルーティング** で作成します。ポリシーは次の要素からなります。

- **モデル名** — クライアントが呼び出す名前。例: `auto/coder`。英数字と `. _ / -` のみ使え、既存のモデルと重複できません。作成すると `/v1/models` に表示され、通常のモデルと同様にトークンや組織の許可リストに追加できます。許可リストはポリシー名で判定され、ターゲットモデルが呼び出し元の許可リストに含まれている必要はないため、高価なモデルや非表示のモデルをポリシー経由でのみ到達可能にできます。
- **判定モデル** — 最初のメッセージを分類する小さく速いチャットモデル。ゲートウェイが提供するチャットモデルならどれでも使えます。指示によく従うものを選んでください。それ自体がポリシーであってはなりません。
- **質問とルート** — 一文の質問と、2 〜 16 件のラベル。各ラベルには短い説明とターゲットモデルを付けます。モデルではなくリクエストを説明し、ラベルは互いに重ならないようにしてください。重なると確率が分散し、リクエストがフォールバックに流れます。3 つのテンプレート（コーディングの変更の大きさ、サポートの振り分け、推論の深さ）が出発点になります。
- **スコアリング** — 確信度の測り方。[スコアリング](#スコアリング)を参照。既定は自動です。
- **フォールバックモデルとしきい値** — 判定が信頼できないときはフォールバックが応答します。最も安全なモデルを置いてください。しきい値（0 〜 1、0.5 が良い出発点）は選ばれたラベルの確信度と比較され、上げると境界的なリクエストがよりフォールバックへ送られます。logprobs でスコアリングする場合の確信度は確率です。自己申告の確信度は順位としてだけ扱ってください。
- **詳細** — セッションを固定する時間（0 なら毎回分類）、判定モデルに送る最初のメッセージの文字数上限、判定のタイムアウト。

**試す** タブは判定ステップだけを実行します。最初のメッセージを貼り付け、必要なら複数の判定モデルを並べて比較できます。転送も課金もセッション固定も行いません。各結果にはスコアリング方法が表示され、logprobs のときは各ラベルの確率も並びます。ポリシーを有効にする前に、ログにある実際の最初のメッセージでテストしてください。

### スコアリング

判定モデルの確信度には 2 つの得方があります。

- **logprobs** — ラベルを文字付きの選択肢として示し、モデルは 1 文字だけで答えます。ゲートウェイは各文字に対するモデルの出力確率を読み取るため、どのラベルにも実際の確率が付き、しきい値がその意味どおりに働きます。推論しないモデルと、logprobs を返すチャネルが必要です。GPT-4.1、思考モードでない DeepSeek、セルフホストの vLLM などの OpenAI 互換 API が該当します。Claude、推論モデル、多くのアグリゲーターゲートウェイは logprobs を返しません。
- **自己申告** — モデルがラベルと、自分で決めた確信度の数値を答えます。どのチャットモデルでも使えますが、この数値は較正されていません。

| 設定 | 動作 |
| --- | --- |
| 自動（既定） | logprobs を使います。判定モデルがあるチャネルで logprobs を返さない場合、そのリクエストは自己申告の確信度で判定し直し、そのチャネルでは以後 24 時間自己申告を使います。 |
| logprobs のみ | logprobs を使います。返さないチャネルではフォールバックモデルが応答します。 |
| 自己申告のみ | 常に自己申告の確信度を使います。 |

設定の横の **対応を確認** は判定モデルに小さなテストリクエストを 1 件送り、今回振り分けられたチャネルが logprobs を返すかどうかを示します。

判定の課金スイッチは **設定 → ゲートウェイ → 自動ルーティング** にあります。

## 組織のポリシー

サイト管理者は組織に自分のポリシーを管理させることができます。**設定 → ゲートウェイ → 自動ルーティング** で **組織が自分のルーティングポリシーを管理できるようにする** をオンにし、必要なら組織ごとに作成できるポリシー数（既定は 20）を変更します。

すると組織の Owner と Admin の組織設定に、一般・メンバー・予算と並んで **自動ルーティング** が表示されます。一般メンバーには表示されません。メンバーは `/v1/models` で組織のポリシーを確認でき、組織の API キーで呼び出せます。

- 組織のポリシーはその組織の API キーにだけ適用されます。個人のトークンや他の組織からは見えません。
- 組織のポリシーはプラットフォームのポリシーと同じ名前にできます。その組織のトークンでは組織のポリシーが使われ、無効にするとプラットフォームのポリシーに戻ります。
- 判定モデル・ターゲット・フォールバックには、その組織がもともと呼び出せて、カタログで非表示になっていないモデルだけを選べます。あとでサイトがターゲットを非表示にすると、リクエストはフォールバックに回ります（理由 `target_unavailable`）。フォールバックも非表示なら、モデルが見つからないエラーになります。
- **試す** と **対応を確認** は判定モデルを実際に呼び出し、費用は組織に計上されます。ポリシーの統計には含まれません。組織側ではログから最初のメッセージを再生できません。
- ポリシーの作成・変更・有効化/無効化・削除は組織の監査ログに記録されます。

サイト管理者は **ゲートウェイ → 自動ルーティング** の **組織のポリシー** タブで全組織のポリシーを確認し、そこで無効にできます。
